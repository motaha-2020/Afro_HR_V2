# Module 04 — Employee Master Data & Digital Employee File

بعد ما بنينا في Modules 01–03:

```text
Tenant / Company
        ↓
Organization Structure
        ↓
Position / Job
        ↓
User / Role / Permission
```

نصل الآن إلى **الموظف نفسه كـMaster Record داخل النظام**.

الهدف من Module 04 ليس مجرد صفحة Employee Profile، بل إنشاء **Single Source of Truth** لكل موظف طوال دورة حياته:

```text
Candidate
   ↓
New Hire
   ↓
Employee
   ↓
Transfer / Promotion / Project Movement
   ↓
Active Employment
   ↓
Offboarding
   ↓
Archived Employee Record
```

وهذا يتوافق مباشرة مع الـPeople & Culture Operations Manual، الذي يطلب إنشاء Employee Record أثناء onboarding، تسجيل الموظف في ERP وPayroll، توليد HR Code، الاحتفاظ بالمستندات، متابعة التغييرات طوال دورة الموظف، ثم غلق وأرشفة الملف عند offboarding. 

---

# 4.1 Core Principle

يجب ألا نبني:

```text
Employee Table
```

ضخم يحتوي كل شيء.

الأفضل:

```text
Employee
   │
   ├── Personal Data
   ├── Employment
   ├── Organization Assignment
   ├── Project Assignment
   ├── Compensation Reference
   ├── Documents
   ├── Contacts
   ├── Emergency Contacts
   ├── Bank Information
   ├── Insurance
   ├── Certifications
   ├── Assets
   ├── Work Eligibility
   ├── History
   └── Lifecycle Events
```

بحيث كل جزء مستقل وقابل للتاريخ والتعديل والتدقيق.

---

# 4.2 Person vs Employee

هذه نقطة أساسية جدًا.

```text
Person
   ↓
Employment
   ↓
Employee
```

لأن نفس الشخص ممكن:

* يترك الشركة.
* يرجع مرة أخرى.
* يعمل في Legal Entity مختلفة.
* يتحول من Outsource إلى Permanent.
* يتحول من Daily Worker إلى Project-Based.

لذلك لا نربط هوية الشخص بوظيفة واحدة للأبد.

مثال:

```text
Person ID: P-000146

Employment #1
AFRO Egypt
2023–2025
Project-Based

Employment #2
AFRO Egypt
2026–
Permanent
```

# 4.3 Employee Number / HR Code

الـOperations Manual ينص على توليد HR Code أثناء System Setup. 

سنفرق بين:

```text
Person ID
Employee ID
HR Code
Payroll ID
ERP ID
Customer ID
```

مثال:

```text
Person ID      P-000151
Employee ID    EMP-2026-00182
HR Code        AFRO-1837
Nama ERP ID    NMA-76451
Payroll ID     PAY-1837
Ericsson ID    ERI-91356
```

لا يجب استخدام National ID كمفتاح Database.

مثال:

```text

```


```text

Sequence
Year Included?
Legal Entity Included?
Project Included?
Leading Zeros
```

لكن بعد إنشاء HR Code:

> لا يتغير بسبب تغيير Project أو Department.

# 4.88 Critical Business Rules

أهم قواعد Module 04:

```text
01. Person can have multiple employments.
02. HR Code must be unique per tenant.
03. National ID must not be primary database key.
04. Employee can belong to multiple projects.
05. Project allocations must be effective-dated.
06. Organization changes must preserve history.
07. Sensitive fields require field-level security.
08. Mandatory documents depend on employee type/role.
09. Deployment requires readiness validation.
10. Changes to master data must be auditable.
11. Data coming from external master systems may be read-only.
12. Employee records must never be hard-deleted.
13. Rehire should reuse Person identity.
14. Future-dated movements must be supported.
15. Every employee must belong to one tenant.
```
