تمام. **Cluster K** من أهم الـClusters تقنيًا لأنه هو الذي يمنع النظام كله من التحول بعد فترة إلى مجموعة جداول متناقضة بين HR وERP وFinance وAttendance وCustomer systems.

هنا لا نبني مجرد “Integrations Module”، بل نبني **Data & Integration Governance Layer** كاملة تحدد لكل معلومة: من هو الـSystem of Record، من يملك حق التعديل، من يقرأ فقط، كيف نكتشف التعارض، وكيف نعيد المزامنة بدون فقد Audit Trail.

# Cluster K

## HR Master Data Migration, External Integrations, Interface Management, Data Quality, Reconciliation, Import/Export, Integration Monitoring & System-of-Record Governance ERD

القاعدة الأساسية:

> **Integration ≠ Data Ownership ≠ Synchronization ≠ Migration ≠ Import ≠ Reconciliation ≠ Data Quality**

كل واحدة لها Lifecycle مختلف.

---

# 1. الهدف المعماري

Cluster K يجب أن يجيب عن أسئلة مثل:

```text
من هو الـmaster للـEmployee Code؟
من يملك Salary؟
من يملك Attendance Punches؟
من يملك Bank Account؟
من يملك Project Code؟
ماذا يحدث إذا ERP يقول أن الموظف Active وHR يقول Separated؟
هل آخر sync نجح؟
ما الـrecords التي فشلت؟
هل تمت إعادة المحاولة؟
هل يوجد duplicate employee؟
هل يوجد employee في Payroll وليس في HR؟
هل هناك Project Code غير معروف؟
هل تم استيراد Excel مرتين؟
من عدّل mapping؟
ما الفرق بين source value وtarget value؟
كيف نعمل initial migration لـ5,000 موظف لكل شركة؟
```

# 177. أهم Business Rules

أثبت هذه القواعد:

1. كل business attribute مهم له owner واضح.
2. لا يوجد أكثر من Master لنفس attribute في نفس الفترة بدون rule صريح.
3. Integration لا يمنح ownership تلقائيًا.
4. External system لا يعدّل HR master data إلا إذا لديه write authority.
5. كل Interface له versioned data contract.
6. Mapping لا يكون hard-coded قدر الإمكان.
7. Reference mismatches تذهب إلى mapping queue.
8. كل message يدعم idempotency.
9. Duplicate message لا ينتج duplicate transaction.
10. Integration failure لا يعني حذف البيانات.
11. Retry bounded وليس infinite.
12. Dead letters لها lifecycle.
13. Sync success لا يساوي reconciliation success.
14. Reconciliation مستقل عن integration execution.
15. Data quality مستقل عن data transfer.
16. Migration لا تكتب مباشرة إلى production.
17. كل migration تمر staging + validation + sign-off.
18. Bulk import يمر preview قبل commit.
19. Sensitive imports تحتاج approval.
20. Export يخضع masking وaudit.
21. Conflict لا يتم حله بـlatest wins افتراضيًا.
22. Master system wins حسب governance rule.
23. كل تغييرات mapping audit-able.
24. Data lineage يجب أن تكون قابلة للتتبع.
25. Credentials لا تخزن plaintext.
26. Logs لا تعرض PII/sensitive data.
27. Payload retention configurable.
28. System access يستخدم least privilege.
29. Interface schema changes versioned.
30. Production mapping changes تحتاج governance approval.
31. Business integration transaction يمكن أن تشمل عدة systems.
32. Employee lifecycle لا يعتبر fully propagated حتى تكتمل required downstream systems.
33. Backfill مطلوب بعد integration outage.
34. File integrations تمنع duplicate file processing.
35. Device mapping effective-dated.
36. External identity mapping لا يكرر employee master.
37. Data sharing only minimum necessary fields.
38. Multi-tenant isolation mandatory.
39. Reconciliation issues لها owner وresolution.
40. Go-live migration يحتاج business sign-off.

# 188. أهم Architectural Principle

أريد تثبيت هذه السلسلة:

> **Source System ≠ System of Record ≠ Integration Channel ≠ Replica ≠ Reconciliation Authority**

قد يكون النظام مصدر البيانات اللحظي لكنه ليس master.

مثال:

```text
Fingerprint Device
```

هو Source للـraw punch.

لكن:

```text
Attendance Engine
```

هو owner للـvalidated attendance day.

وهذا فرق جوهري.
