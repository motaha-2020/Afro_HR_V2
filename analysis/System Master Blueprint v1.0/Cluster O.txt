تمام. **Cluster O** مهم جدًا لأن الوثائق في نظام HR ليست مجرد Attachments؛ هي جزء من **الـlegal record، compliance evidence، workflow approvals، employee lifecycle history، audit trail، والتكامل مع جهات خارجية**.

وفي الـOperations Manual الموجود عندكم، هذا واضح جدًا: onboarding يتطلب مجموعة محددة من المستندات، العقود والتوقيعات، Form 1، NDA، handbook acknowledgment، medical examination، certifications، ثم offboarding يحتاج handover، clearance، Form 6، final settlement، receipt acknowledgments، وأرشفة ملف الموظف. 

لذلك Cluster O يجب أن يكون **Document Platform مركزية** تخدم كل الـModules بدل أن يصبح عندنا:

```text
Recruitment Attachments
Personnel Attachments
Payroll Attachments
HSE Files
ER Evidence
Expense Receipts
Training Certificates
```

وكل Module يخزنها بطريقته.

# 1. Architectural Principle

لا نضع:

```text
employee_contract_file
employee_id_copy
medical_pdf
cv_file
```

كـcolumns في Employee Table.

ولا نخزن Binary Files داخل كل Domain DB.

الأفضل:

```text
Business Domain
      |
      | document_id
      v
Enterprise Document Platform
      |
      +---- Metadata DB
      |
      +---- Object Storage
      |
      +---- Security
      |
      +---- Versioning
      |
      +---- Retention
      |
      +---- OCR
      |
      +---- Signature
```

الـBusiness Module يعرف:

> هذا المستند يخص Employee 1042.

ولا يحتاج أن يعرف أين وكيف خُزن الملف فعليًا.

# 5. Activation Gate

هذه نقطة مهمة جدًا.

الـManual ينص على أن employee لا يتم activation قبل اكتمال المستندات والعقود والموافقات المطلوبة. 

لذلك لا يرسل Onboarding Module مجرد:

```text
Documents complete = true
```

بل يسأل Document Platform:

```text
EvaluateChecklist(
 employee,
 EMPLOYMENT_ACTIVATION
)
```

ويرجع:

```json
{
  "eligible": false,
  "completion": 83,
  "missingMandatoryDocuments": [
    "Medical Form 111",
    "Professional License"
  ]
}
```

# 57. أهم قواعد Cluster O

أعتبر الآتي Non-Negotiable:

1. **Files are not stored inside business-domain tables.**
2. Document metadata منفصلة عن binary storage.
3. كل document لها classification واضحة.
4. كل Version قديمة تظل محفوظة حسب retention policy.
5. Upload لا يعني Verified.
6. Virus scan قبل إتاحة الملف.
7. Sensitive documents لا تستخدم permanent public URLs.
8. Access يتم عبر authorization checks وليس storage path.
9. Digital Personnel File هو logical dossier وليس Folder فقط.
10. Mandatory document requirements تعتمد على Rules.
11. Employee Activation يمكن أن يعتمد على Document Compliance Gate.
12. Expired document لا يُستبدل بصمت؛ Renewal يولد record جديد.
13. ER/legal evidence يجب أن تدعم chain of custody.
14. Medical documents تكون في highly restricted security zone.
15. Legal Hold يوقف disposition.
16. Document deletion يجب أن يكون governed وليس direct delete.
17. Generated documents تحفظ data snapshot المستخدم في التوليد.
18. Signed copy تصبح immutable record.
19. OCR لا يعتبر Verification تلقائيًا.
20. كل View / Download / Share للمستندات الحساسة يسجل Audit.
21. External sharing يجب أن يكون time-limited وقابلًا للإلغاء.
22. Tenant isolation يجب أن تشمل storage وsearch وprocessing.
23. AI لا يحصل على unrestricted access لكل ملفات الموظفين.
24. Raw file binaries لا تمر داخل Event Bus.

هذا separation ممتاز.
