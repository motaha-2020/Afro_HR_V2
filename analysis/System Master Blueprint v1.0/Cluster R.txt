نعم، **Cluster R** هو الخطوة الطبيعية الآن، لكن يجب ضبط حدوده بدقة حتى لا نكرر ما هو موجود في Cluster 03 أو L أو N.
هذا الـCluster لا يعرّف فقط من هو المستخدم وما هي الـRole؛ بل يدير **حَوْكَمة الوصول، الثقة في الجلسة والجهاز، الصلاحيات الحساسة، مراجعات الوصول، الفصل بين المهام، كشف السلوك غير الطبيعي، الحوادث الأمنية، وربط المنصة مع SIEM/SOC**.

والـManual الحالي نفسه يفرض مبادئ تدعم هذا الاتجاه: البيانات الوظيفية والرواتب والتحقيقات يجب أن تكون confidential ولا يصل إليها إلا المصرح لهم، وكل العمليات المهمة تحتاج approvals وقابلية تتبع، كما أن offboarding يتطلب تعطيل كل access بحد أقصى آخر يوم عمل. 

# Cluster R — Enterprise Security Operations & IAM Governance ERD

أقسمه إلى **18 Sub-Domains**:

```text
R1   Identity Federation & SSO
R2   Authentication Policy
R3   MFA / Passwordless
R4   Conditional Access
R5   Device Trust
R6   Session & Risk Context
R7   Privileged Access Management
R8   Access Governance
R9   Access Reviews / Certification
R10  Segregation of Duties
R11  Security Events
R12  Threat Detection
R13  DLP / Sensitive Data Controls
R14  SIEM / SOC Integration
R15  Security Incident Response
R16  Credential / Secret Security Governance
R17  Security Posture & Compliance
R18  Security Operations Metrics & Audit
```

---

# 1. الحدود المعمارية

المهم أولًا أن نفرق بين:

```text
Cluster 03
Identity / Users / Roles / Permissions

Cluster R
Security Governance / Risk / Monitoring / Privileged Access
```

مثلًا:

```text
Cluster 03:
User Mohamed has role Payroll Specialist

Cluster R:
Should Mohamed still have this role?
Was it reviewed?
Is it conflicting with another role?
Is he connecting from a trusted device?
Is this a privileged session?
Was the access used abnormally?
```

# 60. Security Golden Rules

أعتبر هذه القواعد أساسية:

1. **Authentication ≠ Authorization.**
2. Role assignment لا يعني access دائمًا بلا مراجعة.
3. Privileged access يكون JIT حيثما أمكن.
4. Critical roles تحتاج MFA.
5. Sensitive actions تحتاج step-up authentication.
6. Device trust جزء من access decision.
7. Session risk يمكن أن يغير القرار بعد login.
8. Tenant isolation تطبق أمنيًا في كل layer.
9. Access reviews دورية للـhigh-risk roles.
10. SoD conflicts تُكتشف قبل وبعد assignment.
11. Break-glass access مراقب بالكامل.
12. Offboarding يجب أن يؤدي إلى session/access revocation.
13. Service accounts تخضع لنفس governance تقريبًا.
14. Logs الأمنية لا تحتوي secrets.
15. DLP تطبق على export/share/API/AI.
16. SIEM integration لا تلغي local audit.
17. Security Events يجب أن تكون normalized.
18. High-risk actions قابلة للربط بالمستخدم والجلسة والجهاز.
19. Security response لا يتخذ قرار HR وظيفيًا تلقائيًا.
20. Security incident evidence يدار عبر Cluster O.
21. Access decisions يجب أن تكون explainable.
22. MFA reset نفسه action privileged.
23. Security exceptions لها expiry وموافقة.
24. Credential rotation mandatory للـservice identities.
25. Security monitoring يشمل AI/Search/Documents/API events.
26. المستخدم لا يستطيع اعتماد access request لنفسه إذا policy تمنع ذلك.
27. No permanent hidden super-admin permissions.
28. Security posture قابل للقياس وليس policy على الورق فقط.
