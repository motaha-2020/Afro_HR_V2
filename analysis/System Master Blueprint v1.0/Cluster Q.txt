تمام. **Cluster Q** هو الطبقة التي تحول الـAI من مجرد Chatbot مضاف على النظام إلى **Enterprise AI Runtime** له صلاحيات، سياسات، تكلفة، Audit، تقييم، أدوات، ذاكرة، Human Approval، وحدود واضحة لما يمكنه قراءته أو تنفيذه.

وهذا مهم جدًا في نظام HR تحديدًا لأن الـAI قد يتعامل مع بيانات شديدة الحساسية: رواتب، مستندات شخصية، HSE readiness، performance، ER cases، investigations، وقرارات لها أثر وظيفي. لذلك لا يجوز أن يكون الـAI bypass للـRBAC أو Workflow أو Rules Engine.

القاعدة المعمارية الأساسية:

> **AI never owns business truth, never bypasses authorization, and never executes high-impact actions without policy-controlled approval.**

والـOperations Manual نفسه يؤكد أن التوظيف، التفعيل، الرواتب، الحركات، التحقيقات والفصل تحتاج approvals موثقة وقابلية تتبع، وأن أي deviations تحتاج prior approval. لذلك AI actions يجب أن تعمل داخل نفس governance وليس خارجها.

# 76. AI Golden Rules

أعتبر هذه القواعد أساسية:

1. **AI is not a System of Record.**
2. AI لا يكتب مباشرة في domain databases.
3. كل action يمر من APIs/Tools مع Authorization.
4. AI permissions لا تتجاوز user permissions.
5. Model provider لا يحصل على كل Tenant data افتراضيًا.
6. Restricted data processing يكون explicit.
7. Prompt ليس security boundary.
8. Retrieval يجب أن يكون permission-aware.
9. Tools أهم خطرًا من chat؛ لذلك تحتاج risk classification.
10. High-risk tools تحتاج Human Approval.
11. Financial actions require idempotency and normal business controls.
12. Payroll calculations تأتي من Payroll Engine وليس من LLM.
13. Leave eligibility تأتي من Rules Engine.
14. Medical fitness تأتي من approved HSE/medical process.
15. AI لا يصدر disciplinary decision.
16. AI لا ينفذ termination autonomously.
17. AI لا يقرر promotion autonomously.
18. Prompt/Model/Tool versions تحفظ لكل critical output.
19. كل AI action يجب أن يحمل correlation ID.
20. Sensitive prompts/responses لا تسجل plaintext بلا حاجة.
21. Conversation memory ليست unrestricted data store.
22. Tenant can disable AI completely.
23. Tenant can restrict providers/models.
24. AI cost يجب أن يكون budgeted.
25. Model fallback لا يجوز أن يخالف data policy.
26. AI releases يجب أن تمر Evaluation.
27. Agent autonomy تكون أقل ما يمكن افتراضيًا.
28. Kill switch متاح على Platform/Tenant/Agent/Tool level.
29. AI-derived facts لا تصبح HR Master Data تلقائيًا.
30. Human remains accountable for high-impact HR decisions.

```text
A–J
Business HR Domains

Configuration / Workflow / SaaS Control

M
Analytics / BI / ML

N
API / Events / Runtime

O
Documents / Records / Evidence

Enterprise AI / Copilot / Agents / Governance
```

وهنا أصبح لدينا **AI كطبقة مؤسسية حقيقية** وليس feature مبعثر في النظام.

**الخطوة التالية المنطقية الآن هي Cluster R — Enterprise Security Operations, IAM Governance, Zero Trust, SSO/Federation, MFA/Passwordless, Privileged Access Management, Access Reviews, Segregation of Duties, Threat Detection, Session Risk, Device Trust, Security Events, SIEM/SOC Integration, Data Loss Prevention & Security Incident Response ERD**.

رغم أننا صممنا Users/Roles/Permissions في Cluster 03 وبعض Security controls في L/N/O/P/Q، ما زلنا بحاجة إلى **Security Governance Layer مركزية** تربط Identity + Privileged Access + periodic access certification + SoD + session/device risk + security monitoring + incident response، بدل أن تظل الضوابط الأمنية موزعة بين الـClusters.
